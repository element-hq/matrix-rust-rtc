# @element-hq/matrix-rtc

MatrixRTC ([MSC4143](https://github.com/matrix-org/matrix-spec-proposals/pull/4143))
participation for web and Node: the [`matrix-rtc-uniffi`](../crates/matrix-rtc-uniffi)
crate compiled to WebAssembly, with TypeScript bindings generated by
[uniffi-bindgen-react-native](https://github.com/jhugman/uniffi-bindgen-react-native).
The generated API is the participation facade of `matrix-rtc-core`: a host
implements one `RtcCommandSenderCallback` (the six outbound Matrix
commands), pushes room state in through `RtcSessionManager`, and consumes four
outputs per `Participation`: memberships, transports, key map, status. No
media code is in here: a host holds its own LiveKit rooms, one per entry of
`transports()`, and mints the tokens for them.

Not published yet (`private: true`); consumed from this repository.

## Use

```ts
import { initAsync, RtcSessionManager, FfiTransportIntent, FfiRtcTransport, heartbeatIntervalMs } from "@element-hq/matrix-rtc";

await initAsync(); // loads the wasm next to the module; idempotent

const manager = new RtcSessionManager(myCommandSender); // your RtcCommandSenderCallback
await manager.onRoomEncryptionReceived(roomId, true);
await manager.onRoomSlotsReceived(roomId, slots);       // the room's complete m.rtc.slot state
await manager.setCurrentStickyState(roomId, stickyMap); // the room's complete sticky map, on every change

const participation = manager.participation(roomId, "m.call#ROOM", userId, deviceId);
await participation.setMembershipsListener({ onMembershipsChange: (m) => renderTiles(m) });
await participation.setTransportsListener({ onTransportsChange: (t) => holdLiveKitRooms(t) });
await participation.setKeyMapListener({ onKeyMapChange: (keys) => installKeys(keys) });
await participation.setStatusListener({ onStatusChange: (s) => showStatus(s) });

const memberId = await participation.join(
  new FfiTransportIntent.Publish({ transport: new FfiRtcTransport.LiveKit({ livekitServiceUrl }) }),
  { application: "m.call", memberId: undefined, keepAliveTimeoutMs: undefined, stickyDurationMs: undefined, degradedLifetimeMs: undefined, encryption: undefined },
);
const beat = setInterval(() => participation.heartbeat(), Number(heartbeatIntervalMs()));
```

Inputs are push-in and room-scoped: the whole sticky map goes in on every
change (a missing entry reads as a leave), the whole slot state likewise.
Listener callbacks run synchronously inside the push that changed the value
and only when it changed; never `await` a call back into the bindings from
inside one — schedule it. Timings cross as `bigint` milliseconds, and
`Vec<u8>` (media keys) as `ArrayBuffer`.

### Loading the wasm

`initAsync()` with no argument resolves `index_bg.wasm` relative to the module
via `new URL(..., import.meta.url)`; Vite, webpack 5 and Rollup rewrite that to
the emitted asset, Node (through the `node` export condition) reads the file
from disk. To control it yourself pass any of `URL | string | Request |
Response | BufferSource | WebAssembly.Module`:

```ts
import wasmUrl from "@element-hq/matrix-rtc/wasm?url"; // Vite
await initAsync(wasmUrl);
```

Serve `.wasm` as `application/wasm` so browsers stream-compile it. No COOP/COEP
headers are needed: the build is single-threaded.

## Develop

```sh
npm install
npm run build        # crate -> wasm32 (profile `web`) -> wasm-opt -> tsc -> dist/, then a pack check
npm test             # acceptance suites (vitest) against dist/
npm run typecheck    # sources and suites
npm run test:types   # the shipped .d.ts compile with skipLibCheck: false
npm run test:pack    # install the tarball into a scratch Node + Vite consumer (needs network)
npm run dev          # demo page
```

From the repository root: `make web-rtc-build`, `make web-rtc-test`,
`make web-rtc-clippy`, `make web-rtc-dev`.

`scripts/build.mjs` is the build; `scripts/check-pins.mjs` runs first and fails
on any drift between the coupled versions (below). Sizes are printed after
each step.

### Suites (`test/`)

| file | covers |
|---|---|
| `participation.test.ts` | the facade end to end: getters, listeners, join order, keep-alive, status and impairments |
| `encryption.test.ts` | key distribution, inbound verification (cleartext / wrong device), per-tile key state, `LeftWithKeys` |
| `runtime.test.ts` | the runtime assumptions under wasm: foreign promises awaited by Rust futures, `bigint`, no re-entrancy |
| `types/consumer.ts` | the shipped declaration files, from a consumer's point of view |

The suites import the package by name; `vitest.config.ts` aliases that to
`dist/`, so they test what ships, never the TypeScript sources.

### Layout

| path | what |
|---|---|
| `src/index.ts`, `src/index.node.ts`, `src/init.ts` | the entry points (browser / `node` condition) and the shared loader |
| `src/log-sink.ts`, `src/testing/mock-host.ts` | the subpath exports |
| `src/wasm-bindgen-types/index.d.ts` | hand-written types for the wasm-bindgen glue (ubrn emits none); copied next to `index.js` by the build |
| `src/generated/` | **generated** bindings; gitignored |
| `src/app.ts`, `index.html` | the demo page (`npm run dev`), not published |
| `ubrn.config.yaml` | which crate to build (`crates/matrix-rtc-uniffi`) and where the bindings go |
| `Cargo.patch.toml` | merged into the generated shim crate: the wasm-bindgen pin and the size-tuned `web` profile |
| `rust_modules/wasm/` | **generated** wasm shim crate, its own workspace and lockfile; ignored |

### Gotchas

- **Coupled versions**: `uniffi` (`crates/matrix-rtc-uniffi/Cargo.toml`) ↔
  `uniffi-bindgen-react-native` ↔ `@ubjs/core` (both `package.json`) ↔
  `wasm-bindgen` (`Cargo.patch.toml`, must equal the `wasm-bindgen-cli-support`
  compiled into ubrn). Bump them together; `npm run check-pins` is the gate.
  The version in `package.json` must equal the workspace version
  (`npm run sync-version`).
- **Two uniffi versions in the workspace**: this package builds the 0.31 crate;
  the mobile bindings (`matrix-rtc-ffi`) are uniffi 0.29 and never link it.
- **Feature resolver v1 in the generated shim**: `rust_modules/wasm` is edition
  2018, so cargo unifies *target-specific* features into the wasm build. Any
  native-only tokio feature outside `sync, macros, io-util, rt, time` fails the
  wasm build; the crates on the path declare one tokio feature set.
- **ubrn's TOML merge cannot change a value's type**, which is why the size
  profile is a custom `[profile.web]` rather than an edit of `release`.
- **ubrn's host build** runs inside the repository workspace first (to read the
  uniffi metadata), so the crate's `crate-type` includes `cdylib`/`staticlib`.
